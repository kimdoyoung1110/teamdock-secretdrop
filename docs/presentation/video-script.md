# 발표 영상 대본

목표 길이 6~7분. 슬라이드 설명 3분 + 실제 동작 시연 3분 + 마무리 30초.
녹화 전 준비: 배포된 Keycloak 주소를 한 번 열어 깨워 둔다. 브라우저 탭은 TeamDock, SecretDrop 두 개만.

## 1부 — 슬라이드 (약 3분)

| 슬라이드 | 말할 내용 |
|---|---|
| 1 표지 | 암호와인증 SSO 실습 과제 발표입니다. Keycloak으로 두 서비스에 SSO를 적용했고, 그중 하나는 암호학이 적용된 시크릿 공유 서비스입니다. |
| 2 문제 | 팀플을 하면 .env나 API 키를 카톡으로 보냅니다. 그 값은 채팅방에 평문으로 계속 남습니다. 이 문제를 풀려고 팀을 관리하는 TeamDock과 비밀값을 공유하는 SecretDrop을 만들었습니다. "이 시크릿은 우리 팀만"이 되려면 두 서비스가 같은 사용자를 알아야 해서 SSO가 필요합니다. |
| 3 구성도 | 계정은 Keycloak 하나에 있고, 두 서비스는 Keycloak의 클라이언트입니다. 실선은 브라우저를 거치는 흐름, 점선은 서버끼리 직접 통신하는 흐름입니다. |
| 4~5 환경·설정 | Next.js와 Auth.js로 Confidential Client를 구현했습니다. Keycloak에는 realm 하나에 클라이언트 두 개를 두고 PKCE S256을 필수로 했습니다. 설정은 JSON 파일로 두어 docker compose 한 번으로 재현됩니다. |
| 13 동작 원리 | (시연 뒤에 설명해도 된다) A에 로그인할 때 Keycloak이 자기 세션 쿠키를 심습니다. B로 갈 때 브라우저가 그 쿠키를 Keycloak에 다시 보내기 때문에 로그인 화면 없이 code가 나옵니다. |

## 2부 — 시연 (약 3분)

1. **A 로그인**: `teamdock-sso.vercel.app` → 로그인 → Keycloak 로그인 화면이 뜨는 것을 보여 준다 → alice로 로그인 → 팀 만들기.
2. **B SSO**: 팀 화면에서 "SecretDrop에서 시크릿 만들기" 클릭. "지금 주소가 SecretDrop으로 바뀌었는데 로그인 화면이 없었습니다"라고 말한다. 두 서비스의 프로필을 열어 `sid`가 같은 것을 보여 준다.
3. **암호화**: 시크릿을 하나 만든다. 발급된 링크에서 `#` 뒤가 키라는 점을 짚는다. "서버에 실제로 저장된 값 보기"를 펼쳐 암호문만 있는 것을 보여 준다.
4. **열람과 파기**: 다른 브라우저(또는 시크릿 창)에서 bob으로 링크를 연다 → 내용이 보인다 → 새로고침하면 "이미 열람된 시크릿입니다".
5. **권한 거부**: carol로 팀 전용 링크를 열면 "열람 권한이 없습니다".
6. **로그아웃**: SecretDrop에서 로그아웃 → TeamDock 탭을 새로고침 → TeamDock도 로그아웃되어 있다. "강의 예제에서는 여기서 A 세션이 남는데, Back-Channel Logout으로 함께 끊기게 했습니다."
7. **새 브라우저 세션**: 시크릿 창에서 SecretDrop `/new` → Keycloak 로그인 화면.

## 3부 — 마무리 (약 30초)

| 슬라이드 | 말할 내용 |
|---|---|
| 14~16 암호학 | SecretDrop은 브라우저에서 AES-256-GCM으로 암호화하고 키를 링크의 # 뒤에만 둡니다. 서버와 DB가 유출돼도 평문을 알 수 없습니다. 인증 흐름에도 PKCE의 SHA-256, JWT의 RS256 서명이 쓰입니다. |
| 17~18 문제와 소감 | 가장 어려웠던 것은 로그아웃이었습니다. (소감은 본인 말로) |
| 19 링크 | 소스코드와 배포 주소는 마지막 장에 있습니다. 감사합니다. |
